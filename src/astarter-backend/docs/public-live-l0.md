# STA-89 L0: explicit PUBLIC live assembly

L0 is an offline-qualified factory, not a live deployment. `control.public_data_live.create_live_public_app` reuses the existing PUBLIC DAL, pool, providers, shared BFF and authenticated `refresh_once` route. It adds no table, scheduler, budget unit, retry loop or migration. The existing synthetic Preview entrypoint is unchanged.

A caller must supply an independently reviewed `PublicLiveTarget` (exact host, port, database, reader and collector login, target profile and its existing catalog pin). Configuration cannot establish its own trusted target. `raw=None` or exactly `{"enabled":false}` returns a disabled 503 app with no pool/provider construction. Other malformed, duplicate, mismatched or expired settings fail with fixed diagnostics before constructing pools. No environment/credential file is read by the module.

Enabled JSON has these exact fields: `enabled=true`, `mode=live_readonly`, matching `host`, `port`, `dbname`, `reader`, `collector`, `profile`, `catalog_pin`, absolute `expires_at_ms`, and `reader_password`. Secrets are server-owned, never URL/query/client fields. Use no real credentials in tests. The reader service rejects collector passwords, refresh tokens, scopes and vendor keys. The collector service additionally requires its distinct `collector_password`, an ASCII `refresh_token` (32–256 characters), and unique enabled `scopes`. L0 supports `binance` and `coingecko` (the latter requires its Pro API key); BlockBeats remains unconfigured pending actual entitlement. A key's presence is not quota or license proof.

The reader has only the existing snapshot SELECT capability. It cannot inspect or change budgets/attempts. The collector has the existing limited column grants; no role, schema, policy or ledger is created on startup. Actual database/login, native ACL/catalog and mode are checked on each transaction. Collector startup requires three preprovisioned, unexpired live budget rows and no fixture rows/attempts; the reader rejects fixture snapshots. An empty reader snapshot is unavailable, not proof that owner provisioning is complete. A live target must be separately provisioned and pinned in L1: this factory never converts the old fixture database.

Expiry is checked before startup, each request, native checkout, provider transport creation, every HTTP send/return and before committing writes. The existing HTTP transport also rechecks after slot acquisition before DNS and directly before its wire delegate, so queued/DNS work cannot open a new wire after expiry. Database time additionally guards transaction entry/commit. An in-flight request can return after expiry, but cannot become a committed fresh snapshot; the already reserved charge remains, and its unresolved receipt is never replay permission. Existing provider validation, first receipt/source times, financial precision, budget reservation/lease/UNKNOWN and cancellation cleanup are preserved. The factory does not claim a distributed instantaneous revocation boundary or cancel a wire operation already sent before expiry.

Cloud targets require the already-qualified Neon PG17 profile, `sslmode=verify-full`, system CA, channel binding, and the native driver TLS check. Owned local PG17 tests require an injected transport, use Unix sockets only, and explicitly label synthetic wire evidence. No raw DSN, headers, responses or key is part of the evidence.

The factory exposes the four existing data GET paths and existing internal refresh path; no docs/openapi/private/trading routes. All responses are no-store. Origin-bearing requests are rejected, so the future frontend integration must use the approved same-origin server proxy rather than expose the refresh bearer. Public GET never fetches a provider. No source is enabled by adding a new environment variable to the current release app.

L0 tests cover config/default/expiry, real local least-privilege logins, wrong login/database/catalog, fixture rejection, shared read/refresh, expiry rollback and a charged UNKNOWN after send. Existing PUBLIC native tests cover global single-flight, concurrency, idempotency, cumulative budgets, CAS and mixed-source degradation. No real API, Neon, deployment, performance SLA, current database or production acceptance is implied. L1 still needs fresh actual quotas/expiry, fixed target/source manifest, bounded owner/caps and separate authorization.

Local targets reject libpq multi-host strings. The assembly refuses libpq PG* environment fallback keys (values are never read), except existing PG1/2/3_TEST_ROOT/SOCKET fixture markers. It never clears process environment. The gate is repeated before native connections, including pool background replacement. This fail-closed deployment constraint prevents PGHOSTADDR/PGSERVICE/options/client certificate fallbacks from redirecting or altering the explicitly configured connection. L1 requires a dedicated clean runtime; concurrent mutation of process environment is unsupported.
