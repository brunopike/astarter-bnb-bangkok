# Astarter Q03 simulation mathematics

User requested the strategy thread to implement the pure Astarter risk calculator, test it and hand it to the main thread for integration. Main thread verified that request and assigned base `651ca3b9622dd1f63c340fc5b26f06a4b1815b5e`. This spec implements the already selected Q03 design; no further product or runtime authority is introduced.

## Boundary

- Standard library only. Immutable inputs/results, exact bounded decimal strings, explicit base/quote currencies and unit steps. Invalid/missing/nonfinite/float values fail closed with a content-free error.
- No networking, model, native engine, orders, filesystem, database, global account/clock or configuration imports. No `ALLOW` or trade authorization. Results are simulation mathematics candidates.
- Original SMA/S03, Control, runner, schema, dependencies, locks and shared project indexes remain untouched. Main thread owns review and integration.
- Copy the original external 26-vector packet byte-for-byte with its SHA. Use its 18 arithmetic cases; eight state scenarios remain unimplemented and must not be reported passed.

## Arithmetic and API decisions

Use frozen slotted dataclasses and canonical decimal strings publicly. Use bounded Decimal parsing under a local context and exact rational intermediate calculations; format finite results under a private Decimal context. Kelly is advisory, rounded down to a declared fractional quantum for recurring rational values. No global context changes.

Functions: `spot_costs`, `size_spot`, `basket_costs`, `size_basket`, `remaining_budget`, `staged_risk`, `profit_lock`, `kelly_advice`, `lp_budget`, `atomic_cost_floor`. Their complete typed signatures travel in the implementation/handoff.

- Spot: explicit pressure price, positive quantity/quote step, fees [0,1], permitted risk/notional/cash, per-order minima. Round quantity down; ceil fees plus RC04 one-quote-unit-per-possible-fill upper bounds. Binary search quantity steps so extreme precision cannot cause a linear decrement loop. Zero-fee profiles retain the conservative RC04 rounding upper bound; it is not an actual fee claim.
- Basket: fixed requested layers are evaluated together; sizing weights preserve exact layer ratios by using a common rational coefficient compatible with every layer step. Remove both denominator and numerator common factors, so scaling every weight by the same factor cannot change the resulting orders. Return `first_layer_quantity`, an actual finite step-aligned quantity; the internal coefficient may be recurring and is not exposed as decimal text. At most 16 layers. All layer minima must pass; never round up to meet minima. A strategy-specific prohibition on additional live layers is owned by Q04, not this calculator.
- Remaining budget: PRIVATE/CYCLE/DAY/PORTFOLIO/ASSET/CORRELATED/EVENT must each explicitly include cap, booked debit, current-to-stress inventory loss and unresolved pending loss. Show over-limit and zero remaining without hiding negative headroom. No source/epoch/CAS validation is claimed.
- Stage: explicit card/policy caps and allowed account/stage multipliers; optional Kelly cap is absent when OFF. A zero stage gives zero candidate risk. No mode activation or evidence upgrading.
- Profit reserve: explicit settled net profit, old HWM/reserve and settlement-ready flags. Lock only positive new profit-HWM increment; preserve HWM/reserve after a loss, and return even negative tradable equity honestly. This exact logical reserve has no transfer/settlement rounding; integration must declare ledger precision and its conservative rounding policy. No claim of persistence, settlement truth or transfer.
- Kelly: p in [0,1], positive net payoff, fraction in [0,1], advisory only; never infer p from score or model confidence.
- LP: full principal plus explicit gas versus remaining pressure budget; nominal cap cannot override pressure. Round requested principal and gas upward to quote units; rounded principal must also fit the nominal cap. Chain capability is not established.
- Atomic: output already net of pool fees/taxes; deduct only explicit gas/external/failure buffers, ceil minimum output. The net output must meet this rounded minimum to pass the cost floor. Cost feasibility never authorizes execution.

Input scalar text is bounded to 64 characters; output scalar text to 256. Internally generated quantities do not go through the external 64-character input parser. Callers must validate any separately re-submitted output against that public input bound. Tuples are required for collection inputs; revalidate nested values at each public boundary. Currency identifiers are bounded uppercase ASCII, with distinct base/quote for spot. Decimal precision is isolated; no monetary float conversions. All result types carry frozen, serializable `scope=SIMULATION_MATH_ONLY` and `execution_authorized=False` fields that cannot be supplied as constructor overrides.

Test real functions; expected values come from the unchanged external packet and hand arithmetic. Module imports/calls must not perform I/O or modify Decimal context. Test frozen inputs/results and no execution permission.

Run focused domain tests, strict mypy, Ruff and full Engine tests on the fixed branch. One fresh whole-branch review, then reproduce/fix material findings and rerun affected gates. Handoff includes commit, paths, signatures, source hash, actual tests and exclusions; no merge/push/deploy.
